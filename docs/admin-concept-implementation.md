# Administration concept implementation

## Phase 0 — Inventory and design alignment

Completed on 2026-11-11 against the local implementation. Scope: inventory, design alignment and a concrete implementation checklist. Application behavior, permissions, API contracts and database schemas are unchanged. No application server or development database was started or modified.

The phase numbering follows [the concept](admin-concept.md#5-phased-implementation-plan): Phase 0 is the first phase; the audit foundation is Phase 1. Outstanding work is collected in the [administration backlog](roadmap.md#platform-administration-and-moderation). The concept supplies the detailed acceptance requirements; this document records findings and completed work.

### Authentication and request boundary

`apps/api/src/auth/routes.ts` installs the shared pre-handler for required password changes and pending cookbook identity repairs. `apps/web/src/middleware.ts` protects administration document routes and forwards API requests. `apps/web/src/lib/server/request-origin.ts` allows safe methods and same-origin requests; unsafe form or content-type-less cross-origin requests are rejected, except the OAuth token form endpoint. Non-form content types pass that check. `apps/api/src/app.ts` registers no CORS plugin or separate Origin/CSRF guard; route authorization remains mandatory even when accessed directly. New administration workflows must use the existing session/proxy boundary deliberately, and their denial tests must exercise direct API calls as well as UI access.

### Audit design decision

Use a separate additive administrative audit table and shared administrative operation service in Phase 1; keep tenant-local `audit_event` semantics intact. The decision and its retention/deletion boundaries are recorded in [ADR 0002](adr/0002-administrative-audit-foundation.md). This is a design decision only: no new table, service or audit-view API is delivered in Phase 0.

### Migration and deployment compatibility

- The local migration sources are `20261030204936_initial_schema.sql` and `20261109230236_cookbook_name_reset.sql`. Schema findings above are based on these sources and their callers; no live database ledger or data consistency was queried.
- `packages/db/src/migrate.ts` discovers sorted SQL migrations, serializes migration execution using an advisory lock, verifies applied checksums and commits each migration with its ledger row in one transaction. Unknown applied IDs and changed checksums abort startup. `apps/api/src/index.ts` runs migrations before serving requests.
- Phase 0 adds no migration. Phase 1 must add a new production migration named using its actual UTC creation time in `YYYYmmddHHiiss` format. Do not change either applied source or rewrite old audit rows into an invented historical admin trail.
- Back up the database before deployment. An additive table permits retaining data while reverting feature usage in a compatible application build, but **an older binary lacking the new migration ID will refuse startup**. Do not delete ledger rows to force a downgrade. Use a forward correction or a coordinated database/application restore; do not drop surviving audit data as a routine rollback.
- Test on disposable PostgreSQL using `apps/api/test/helpers/disposable-postgres.ts`, which starts an isolated container on a random loopback port. No development DB reset or project dev server is needed.

## Phase 1 — Administrative audit foundation

Implemented on 2026-11-11. The shared operation services and retention lifecycle are implemented and tested independently of product inspection/transfer workflows. Existing tenant-manager permissions, cookbook access, reports and owner behavior are unchanged.

### Delivered functionality

- `apps/api/src/admin/authorization.ts`: a dedicated session-only sensitive-administration guard checks human account/principal activity, session lifetime/revocation, explicit `instance:administer`, required password changes and pending cookbook identity repair. Bearer headers are denied even when accompanied by an administrator session.
- `apps/api/src/admin/audit-input.ts`: mandatory trimmed purpose (1–2,000 code points), optional existing-report UUID correlation, rejected unknown attribution fields and bounded allowlisted state metadata.
- `apps/api/src/admin/audit-operation.ts`: server-defined action/target context, atomic work/event mutations, read-only inspection callbacks, reauthorization and durable audit before returning reads, fail-closed errors and safe structured denial/failure logs. Callers must scope target lookups and use the supplied transaction client; they must not send responses from callbacks. No administrative product endpoints were introduced.
- `packages/db/src/migrations/sql/20261111222940_administrative_audit.sql` and `packages/db/src/schema.ts`: separate normalized event and retention-policy tables. Event IDs, historical actor/target/cookbook/report identities, UTC database timestamps, reason, minimal state, text request IDs and successful outcome survive live-resource deletion. Failed attempts use security logs rather than falsely successful database events. The existing tenant-local table and writer are preserved; no historical audit data is relabelled.
- `apps/api/src/admin/audit-retention.ts`, `admin-audit-maintenance.ts`, `index.ts` and the API package script: operator-configurable retention (default 365 days, range 1–3,650), explicit pruning, startup and three-hour periodic pruning. The [operator guide](administrative-audit-operations.md) covers database privileges, backup retention and restoration.

The architecture describes the [implemented infrastructure](ARCHITECTURE.md#administrative-audit-infrastructure); [ADR 0002](adr/0002-administrative-audit-foundation.md) records the design rationale. The roadmap no longer lists the delivered Phase 1 scope. No public API, request/response shape, authentication scheme or UI strings were added or changed, so `contracts/openapi.yaml` and locale dictionaries need no changes. Test handlers exist only in the test suite and are not registered by the application.
